# Regent / 858a 生成失败：根因复核与改进建议

日期：2026-09-19  
性质：技术分析与验收建议；不替代唯一开发计划，不代表线上重新认证。  
复核对象：`858a-failure-deep-rca.canvas.tsx`。用户给定路径中的用户名为 smac2025；本机实际文件位于 `C:/Users/showmac2025/.cursor/projects/c-regent/canvases/`。

## 1. 执行结论

原分析的主要方向成立：应分别诊断章内内容修复、作品级连续运行、质量门和验收方式，不能把监督脚本生成样章视为产品自主连续创作已经通过。

但原文将部分代码风险和二手运行描述写成了确定根因。当前最强证据是：**分场生产的整章核验没有失败场定位字段，硬失败后固定重写末场；作品恢复与章任务恢复没有完整衔接；部分审核判断仍依赖问题文本进行软化。** 这些问题应优先处理，尚不足以证明它们解释了 858a a4/a5 的全部失败，也不足以排除模型和创作输入的影响。

建议采用“修复定位与证据闭环优先、连续运行独立验收、模型能力受控对照”的路线，不先扩大导演架构、增加无条件重试或降低真实事实门槛。

## 2. 证据范围与可信度

本轮只读核验了当前工作树、原 canvas、858a 本地产物、监督脚本、历史计划及实验记录。未执行线上数据库查询、部署、付费模型生成或新一轮测试。

证据分三级：

- **A：当前代码直接确认。** 能证明实现行为，不能单独证明某次历史运行实际走过该分支。
- **B：已有运行文件或历史复核记录支持。** 结论只适用于记录对应的运行与版本。
- **C：原文陈述或合理假设。** 仍需原始轨迹、正文版本和请求响应证实。

本地分支为 `main`，HEAD 为 `b97ac72`，存在大量未提交及未跟踪改动。HEAD 不能代表本次完整工作树，也不能代表线上部署版本。上线复验须另外保存文件清单与内容指纹。

## 4. 已确认的技术问题

### 4.1 整章错误与局部修订目标没有可靠映射

`directing_contracts.py` 中，独立审校的 ChapterValidation 有 failed_scene_index；生产 ScriptChapterValidation 只有 hard_fails、soft_notes、facts。`directing_script_loop.py` 的 VALIDATE 硬失败分支固定选择末场。

因此，前场重复、前场状态冲突或跨场问题，可能被交给末场执笔处理。此时模型即使正确修改了收到的末场，也无法消除原错误。这里的直接问题是修复任务定位不足，不是重试次数不足。

推荐使用稳定 scene_id、正文版本、证据片段和问题范围定位。单个 failed_scene_index 只是最低补丁：跨场重复需要同时标明多个场，索引也会随重排变化。无法定位时应明确返回无法局部修复，不能默认修末场。

### 4.2 局部回退依赖隐含列表不变量

WRITE_SCENE 以 scene_index 选场景卡，却以 scene_texts[-1] 取旧稿并替换正文。REVIEW 回退当前会保留目标场并截断后续场，这能维持部分路径的正确性。

建议显式验证“卡、旧稿、入口状态、修订票据属于同一 scene_id 与正文版本”，并对修改中间场后的下游状态失效做统一处理。不能仅把 [-1] 改成 [idx] 就宣布闭环修好；入口快照、场记、拼接稿和调用身份也必须一致。

### 4.3 软问题分类与硬事实边界仍不可靠

当前代码已明确阻止 front:redundant 在所检查的 VALIDATE/REVIEW 分支被直接软化，这支持“本地防重复误放行规则已收紧”，不等于线上 a4 已由本轮认证。

与此同时，场景审核 `_audit_cont_softable` 仍可在没有 critical_missed 时软化纯 continuity_block，或按“入场、连续、重复”等描述关键词判断是否可软化；整章审校也存在按软问题分类改写 passed 的路径。

真实矛盾、摘要滞后、空间省略和审美建议必须按证据区分。修订耗尽只应改变恢复策略，不应改变同一事实问题的严重性。建议保留原审核结果，分别记录硬门结果、创作评价、软问题处理与最终接受决策，避免覆盖 passed 后丢失判断来源。

### 4.4 连续创作与有效恢复是独立产品缺口

`works_volumes._after_chapter_completed` 的非末节点分支不创建后继章；`works_runtime` 领取已有运行；`works_run_control.resume_work` 没有把终止失败章转为可领取状态。监督脚本包含开章、regenerate，甚至直接调整数据库状态和租约的代码。

这些证据足以说明监督运行与真实产品入口并不等价。但“章间没自动衔接”不会直接造成一个已经运行中的章节核验失败，两类问题必须分开统计、分开修复。

## 5. a4/a5：当前能说什么、还缺什么

原 canvas 描述 a4 使用约 50.7 万 token 后因 front:redundant 停止；a5 约 2251 字，经审校回退后以“修复没有改变正文”停止，并涉及钥匙、林见鹿及记忆代价。

本轮在检查的仓库 R3 文件中未定位到可独立核对这些具体数字及完整过程的 a4/a5 原始日志，因此将其保留为**待核运行描述**，不作为本报告已验证的实验结果。已有 evidence_858a_sup.json 可以支持历史章状态与记忆信息，不能替代该两次尝试的完整轨迹。

确认直接根因需要补齐：

1. work_id、run_id、attempt、时间、执行器、模型和部署源码指纹。
2. 首次失败报告及证据所在 scene_id；重复须给出两个位置。
3. 每次修订的场景卡、旧稿、入口状态、完整意见及实际模型请求。
4. 返回稿、保存稿、整章拼接稿的 hash 与差异，验证模型没改、输出未应用、改错对象或旧产物复用中的哪一种。
5. 修订前后同一问题的结果、新增问题及调用/token/金额；“正文未变”只证明比较对象的 hash 相同，不自动说明模型忽略意见。

只有这些证据串起来，才可将“定位缺陷”从高优先级代码问题升级为 a4/a5 已确认的直接根因。

## 6. 架构、模型与提示词的归因

| 因素 | 当前判断 | 所需对照 |
|---|---|---|
| 流程与状态架构 | 已确认存在影响稳定性的实现缺口；未证明导演式总体路线错误 | 在相同失败输入下验证正确定位和状态恢复能否消除失败 |
| 提示与创作输入 | 历史题材调整后人工评价改善，说明影响显著；该变化同时涉及题材，不能只归于提示词 | 同模型、同输入素材，比较明确且完整的修订任务与旧请求 |
| 模型能力 | 未被排除，也未被证明是首要根因 | 固定输入、协议、预算口径与盲评标准，对照模型并保留全部失败 |
| 审核器 | 既可能拦住真实错，也可能误判；应测准确性 | 人工标注真实矛盾、允许回忆、摘要滞后和审美意见，测误放与误拦 |

历史实验显示“系统完成”和“愿意继续阅读”并不一致。工程可运行、事实一致、文学可读性必须分别评价，不能相互替代。

## 7. 建议实施顺序与验收

| 顺序 | 工作 | 可验收出口 |
|---|---|---|
| R0：证据基线 | 冻结 a4/a5 与当前失败样本、正文版本及源码指纹；区分人工/监督干预 | 任一结论都能追到具体运行、输入与结果；不以替换失败样本凑成功 |
| P0：修复定位 | 统一 VALIDATE/REVIEW 问题结构，按 scene_id 定位；统一回退和下游失效 | 前场、中场、末场、跨场重复四类反例均改对位置；保留无关已接受内容 |
| P0：质量边界 | 删除凭关键词误放真实矛盾的路径；保留原判定与例外依据 | 注入真实矛盾必拦，合理回忆不误拦；修满不改变问题性质 |
| P0：修订验收 | 为问题保存稳定 ID、证据、预期事实/删除项、版本和验证规则 | 原问题确实消失且未引入硬错；无进展有界停止；旧稿/错误版本不被复用 |
| P0：恢复闭环 | 按失败原因恢复章任务并准确展示阻塞状态 | 恢复后有可领取任务或明确待处理原因；不跳过失败章、不重复计费 |
| P1：连续运行 | 显式作品级授权范围、幂等后继章、持久待办及补偿 | 一次启动、关页后台三章；重启/并发不重复开章；目标达到即停 |
| P1：跨章事实 | 正文证据绑定权威版本；重复检索仅产生候选，结合状态变化判断 | 道具、人物知识、能力代价和承诺的因果链正确；旧尝试不贡献失效事实 |
| P1：卷末与调度 | 扩卷确认闭环、候选窗口公平性及旧调用键兼容 | 卷末动作可执行；阻塞作品不饿死其他作品；升级恢复不重复消费 |
| P2：工程治理 | 整理脚本、统一部署指纹、同步权威计划和实际验收 | 可复现同一版本；产品验收无需临时数据库修补 |

结构化修订票据应是小型领域契约，不必引入完整道具状态机。must_remove 应指向有版本的证据片段，required_state 应引用已核事实，不能把未经核实的模型判断强制升级为正史。

## 8. 复验指标与发布条件

先做不付费的真实失败回放和状态机测试，再运行有预算上限的小规模真实模型验证。使用未修改监督状态的产品入口进行最终认证。

- 工程指标：章完成率、修订成功率、同问题复发率、人工/监督干预次数、恢复成功率。
- 质量指标：真实事实错误、审核误放率与误拦率，以及独立盲评的阅读意愿、人物可信度、节奏和代价兑现。
- 成本指标：每个最终合格章的全部调用、token、费用与时延；失败尝试必须计入。
- 连续性指标：一次授权后完成三章、断点恢复、跨章承诺兑现和卷末状态闭环。

阈值应在正式对照前冻结；三章仅是短程出口，不代表长篇质量认证。业务成功应同时满足可靠运行、真实硬事实通过及人工阅读评价，而非仅 CANONIZED 或正文非空。
