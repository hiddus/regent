## D1 · P1：未重复提及旧值，不等于实体状态已经改变

位置：`core/src/regent/novel/domain/scene_card.py:299–319`，`_prior_ending_contradicts_state`。

当前规则是：实体 key 出现在前场结尾、旧 value 没出现，就认定前场记载了不同值，允许摘要滞后例外。实际上“没有写旧值”不等于“写了新值”。

### 本轮完整审核复现

- working_state：`{"钥匙": "甲持有"}`。
- 入场摘要：钥匙仍由甲持有。
- 已接受前场结尾：钥匙泛着微光，屋外雨声渐密。
- 当前正文：乙握着钥匙开门。
- 审核问题：入场状态记录钥匙在甲手中；上场结尾没有发生交接，本场却直接写钥匙在乙手中。
- continuity_ok=False，无其他 hard_fails。

调用完整 evaluate_scene_audit，实际 **blocking=False**。前场只描写钥匙外观，没有任何归属变化；真实矛盾仍被放过。

这与上一轮是同一关闭要求，不是新增质量标准。修复必须证明同一实体属性出现已接受的新值，不能用“旧值不在这段文本中”替代证明。

### 最小关闭条件

1. 没有明确、可核对的属性变化证据时，返回“无法证明滞后”，保持阻断。
2. 若尚无结构化来源，可暂时关闭这种自动降级，保留审校结果供有界修复；不要继续扩大词表或猜测新值。
3. 增加“只提及实体外观”“同义描述旧值”“真正交接产生新值”三个完整审核反例。
4. 跨实体状态须按问题涉及的实体/属性判断，不能由无关状态值的匹配决定该问题是否放行。

## D2 · P2：beat_ids 没有进入真实模型输出 schema

位置：`core/src/regent/novel/application/directing_contracts.py:208` 的 LocatedIssueSpec；`directing_script_loop.py` 的 `_verify_model_location`。

定位助手读取 data.beat_ids，新增测试也直接传字典验证映射。但生产使用 ScriptChapterValidation.located_issues，其元素类型 LocatedIssueSpec 没有声明 beat_ids。Pydantic 解析后该额外字段被忽略，model_dump 不再包含它。

### 本轮复现

相同输入：code=missing_beat、scene_ids=[s0]、beat_ids=[b0]、message=缺少关键节拍，message 不含 b0。

```text
直接将字典交给定位助手 -> ('s0',)
LocatedIssueSpec.model_validate(...).model_dump() -> 不含 beat_ids
将解析结果交给定位助手 -> None
```

因此测试证明了助手支持该字段，没有证明实际模型响应能传到助手。生产可能错误停在“无法局部定位”，或退回 message 的字符串搜索。当前提示只说明 scene_ids/evidence_quotes，也没有定义 beat_ids 的填写契约。

### 最小关闭条件

1. 在 LocatedIssueSpec 显式声明 beat_ids，并在模型核验任务中提供可用 beat_id 与 scene_id 对应关系、填写要求。
2. 无引文节拍定位只按显式、合法 ID 处理；未知 ID 拒绝，不以子串匹配代替身份映射。
3. 将现有字典单测升级为 ScriptChapterValidation 解析 → model_dump → _begin_located_scene_repair 的生产路径测试。
4. 验证 b1 与 b10 不互相命中，混合有效/无效 ID 不被静默视为全部有效。
