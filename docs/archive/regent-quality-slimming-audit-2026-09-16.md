# Regent 输出质量与项目精简审计

审计日期：2026-09-16。本报告是当前工作树的观察记录，不是新的产品计划。

## 范围与结论

按 README 的当前定位评估：Novel Engine 是唯一对外产品，Regent Core 是内部内核。检查本地未提交代码、样章、实验产物、部署脚本、测试和 CI；未连接生产服务、未调用付费模型、未做新的人类盲评，也未删除或修改业务代码。工作树已有大量修改、新增文件及归档移动，不能把 Git 中的删除条目直接当作可清理垃圾。

**质量仍有明显改进空间。已经能出现可读样章，但还没有证据证明当前默认链路能稳定、经济地产出连续可读章节。最先要修的是验收语义与状态污染风险，其次是阅读质量闭环；不应先增加更多角色、检查层或重试。**

项目精简应先处理过期门禁、一次性脚本、文档冲突，再解除旧应用交付链路与启动入口的耦合。不能按“不是小说目录”直接删除整个 Core。

## 一、输出质量的具体改进项

### Q1 / P0：修复耗尽不应自动改变事实正确性的标准

直接证据：`core/src/regent/novel/application/direction.py:3138`，场景最多修两次；修满后只有 `critical_missed` 必须停止，其余 `hard_fails` 与连续性问题进入 `scene_soft_fails`，随后仍合并 `audit.state_changes` 并推进场景。

本轮在内存 SQLite + 假模型下调用真实 `produce_tick` 复现：

```text
输入：must 节拍有正文证据；continuity_ok=False；hard_fails=[causal endpoint changed]；已修两次
输出：phase=ASSEMBLE_CHAPTER，scene_index=1
working_state={'before':'ok','unverified':'merged'}
soft_fails=['s1:causal endpoint changed','s1:cont:contradicts established state']
```

这是当前执行路径的行为，不是根据旧报告推测。探测没有发外部模型请求，没有改变仓库文件。

同类风险在整章审校：`direction.py:4666` 后，达到章节修复上限、且导演创作验收通过时，只特殊保护 `[front:]` / `[pov:]`；其他问题整体进入 `soft_continuity`，并把 `review.passed` 设为真。原始审校 `passed=False` 也可能因此被覆盖。

建议：问题以结构化类型、严重度、证据定位表示；已成立的身份/因果/事实矛盾不可因重试耗尽自动降级。耗尽后保存稿件和检查点，暂停或退回规划。允许降级的审美建议必须有明确白名单。将“流程完成”“有缺陷草稿”“核验通过”“创作验收通过”分开统计，不能共用一个 passed。

验收：注入连续性矛盾、因果终点改变、伪造事实，即使预算耗尽或导演接受，也不得写入后续状态和正式事实；真正的文风建议不阻断。

### Q2 / P1：责编有调用成本，但缺少可读性修订闭环

`application/editor_audit.py:51` 将全部已知责编规则强制转为 soft，包括同章矛盾、信息欠账、重复、因果脱节和术语难懂。`direction.py:4585` 仍执行专门模型调用；返回结果记录到 `editor_soft_issues`。对当前后端和 novel-web 的检索未找到该字段的后续修订消费者。

这不代表所有问题都完全无人检测：VALIDATE、ChapterValidation 与前置门仍在。但“责编发现问题→稿件变好”这一条链没有闭合。

建议：保留非阻塞的审美提示，减少每章固定调用；对证据充分、可局部修改的可读性问题，允许预算内一次局部修订并重新核验。若暂不消费结果，就改为抽样离线评估，别每章支付同样成本。严禁把所有 soft 再一刀切变回 hard。

### Q3 / P1：单作品补丁混入通用质量规则

`domain/prose_front_gates.py` 的题名检查写死“林晚/沈栀”，`domain/world_bible.py:475` 将宿主限定为“沈栀/林晚”、穿越者限定为“陈默”。章审校里也有按这些名字降级大纲问题的逻辑。

`_power_surface_fails` 主要检查系统、抽取、羁绊等固定词是否出现。它只能证明词出现，不能证明读者理解了能力、边界与代价。`_near_duplicate_paragraph_fails` 主要覆盖精确重复或包含关系，覆盖不到语义重复铺陈。

建议：人称与身份约束来自作品结构化设定（宿主、意识主体、叙述名），样本人名仅留在测试夹具；题名默认编号也不应跳过全部题文检查。能力兑现用实际行动和代价的正文证据衡量，关键词只能作为提示信号。

### Q4 / P1：最近样章可读性有进展，但场景衔接与信息效率仍弱

不能继续沿用“所有样本都不可用”的早期结论：`docs/novel-quality-ab-experiment.md` 最后一轮已记录人工反馈“已经够用”，同时指出钩子浅、套路明显。该反馈针对当时的金手指 A/B/S 样本，不代表当前默认四剧本分场链路已经胜出。

本轮实际阅读两份较近产物：

| 样本 | 已有优点 | 仍可改善 |
|---|---|---|
| `deploy/novel/_tmp_a41_sample.txt` | 抽取消耗、技能效果、眼前压力更具体，角色选择能跟上 | 同一次“手指偏向情绪伪装又拽回”写了三次；外卖比喻与解释较密。开头从挂断动作切入，若作为完整首章，身份与情境锚点仍偏晚；该文件是临时样本，完整性未认证 |
| `deploy/novel/artifacts/serial_ent_gender_x3/novel.txt` 第一章 | 有受压、反击、代价和暴露风险 | 同章到约第 91 行又回到身体陌生感和穿越身份说明；容易产生第二次开场的感觉。能力调用规则先由旁白直接宣布，角色如何确认规则的过程较弱 |

建议把正文改进聚焦三项：首场让读者迅速知道谁、在哪、想做什么；每场只增加新的选择/信息/后果；能力规则通过行动验证，避免说明面板和旁白替代戏。场景装配增加边界检查，专门找“重复开场、时间回跳、已发生事件再发生”。这些是本轮编辑阅读判断，不是用户盲评成绩。

### Q5 / P1：完成量、成功率与成本应拆开

本地产物中：

- `serial_ent_gender_100k/summary.json`：65 个章节条目，45 个 completed，101,828 字，431 次调用。该历史记录不能表述成“65 章全部验收通过”。当前脚本已限制未通过正文进入书稿，不能据旧产物反推当前仍有同一污染缺陷。
- `serial_ent_gender_x3/summary.json`：3 章 completed，同时记录 2 次失败，81 次调用、10,551 字，16 条开放钩子。按三章摊分是每章 27 次调用，值得优化，但仅这一题材和运行，不能当整体成本统计。
- `serial_ent_gender_100k_x/summary.json`：0 章、3 次失败、18 次调用。必须保留在可靠性分母中。
- `quality_ab_live_power_abs/summary.json` 的 S 平均粗估费用高于 A/B，但与当前四剧本分场实现不同，不能直接证明当前架构不值得使用。

建议固定输入、模型、预算、源码摘要、执行器版本，保留全部失败尝试；同时报告每次尝试成功率、最终成章率、每千合格字成本、修复开销、读者续读意愿。先三章连续验收，再十章，再扩到更长；不能用累计字数替代连续阅读质量。

### Q6 / P1：实际默认链路与实验文档漂移

`application/executor.py:35` 的默认已是 `director_script_scene`，而质量实验文档仍保留“默认 director_v2、script 仅灰度”的现行表述。源码默认和实验描述已不同；历史证据不能自动认证最新默认实现。

建议将文档变更史归档，活跃部分只保留当前默认、唯一对照、晋级证据和未完成事项。每次影响行为的变更更新版本/源码摘要，避免多个实现共用同一个版本标签。

## 三、优先处理的工程卫生问题

### H1：旧定义冻结门禁已经失效

`tests/architecture/test_regent_definition_freeze.py` 仍要求 `docs/definitions/REGENT-DEFINITION-3.0.*`；资料已移到旧路线归档。本轮该文件出现 8 个失败。`.github/workflows/ci.yml` 还直接断言旧路径存在，因此即便只调整测试，CI 后续也会失败。

应替换成当前产品唯一权威源、归档不生效、内核边界的守卫，移除旧产品仍须作为规范源的断言；不要恢复旧文件来假装修好门禁。`tests/README.md` 的“有效/已闭环”描述也需同步。

### H2：卫生检查本身依赖未跟踪、被忽略的脚本

`tests/unit/ops/test_repo_hygiene.py` 导入 `ops/check_repo_hygiene.py` 以及 `ops/archive/oneoff/graduation_harness.py`。本机都有，因此测试通过；但 `git ls-files` 未列出这两个文件，`git check-ignore` 确认它们被忽略。

这意味着该测试不能仅凭当前 Git 内容在干净检出中重现。耐久卫生工具应迁入正式目录并跟踪；旧“十个交付回归目标”断言应按产品范围退役或提取真实仍有效的契约。

现卫生工具只检查根目录 `*.py`，不会发现 `deploy/novel/_tmp*` 的堆积。扩大检查到指定活跃目录，并给正式入口明确白名单。

### H3：测试目录和行为配置漂移

根 pytest 配置 `testpaths=['tests']`，但 `core/tests/` 还有 `test_environment_heal_memory.py` 与 `test_host_resources.py`。默认 pytest 不从这两个位置收集。应统一到根测试树或明确配置收集路径。

本輪定向质量/行为/卫生组合：**83 passed，3 failed**。三项失败分类：

1. `test_real_audit_exhausted_stops_without_advancing_scene`：夹具假定修一次已经耗尽，生产现在是两次。
2. `test_real_audit_rejects_ungrounded_evidence`：同一上限漂移。仅在内存中把夹具已修次数改为 2 后，两项真实行为检查均通过。不能把它们报告成“缺必需节拍/伪证据必然放行”。
3. `test_validate_chapter_script_scene_rewinds_write_scene_not_watch_prose`：假模型只准备一份 ChapterValidation，新增责编调用耗尽假响应，触发 CallUnknown。应补齐响应后再验证回退行为，当前失败尚不能证明回退逻辑坏了。

上面的真实降级放行缺陷由独立探测确认，与两条陈旧测试失败不同。部分闭合测试直接复述分支常量和路由字符串，应逐步换成真实 produce_tick/validate_chapter 的行为断言。

## 四、建议落实顺序与验收

1. **先恢复可信基线**：记录当前工作树快照；更新旧定义门禁与 CI；补齐受跟踪工具；修复测试夹具和漏收集目录。不要回滚用户现有改动。
2. **修复质量放行边界**：场景/章节验收使用同一严重度策略；事实错误不随重试次数降级；失败稿不能污染状态；以真实调用链反例验证。
3. **收敛可读性闭环**：移除样本人名硬编码；修正分场重复开场；责编只保留能改善正文或提供抽样评估价值的部分。
4. **清理低依赖内容**：缓存、一次性脚本、旧桌面壳、演示材料；保留必要证据和最终成果。一次性脚本能力合并成参数化 inspect/run/resume/export，而不是保留第 N 个 poll/rerun。
5. **隔离旧产品运行面**：小说独立启动配置→停挂旧 API/任务→验证创建、生成、暂停、恢复、预算、导出→再删旧业务模块。数据库表和迁移另行处理，不与源码清理混成一次操作。
6. **用固定三章/十章实验决定架构取舍**：当前默认与一个对照，同预算同输入，保留全部失败；盲评续读、清晰、人物选择、重复与兑现。证据不足就保留不确定性，不能把 CANONIZED 或测试全绿当文学质量通过。

本轮没有运行全仓测试、生产 PostgreSQL 认证、前端浏览器旅程或最新默认执行器的真实模型复测。结论只覆盖上述检查范围；报告生成是唯一主动新增的项目文件。
