# 小说质量需求与验收标准 v1

> 适用范围：legacy_v1 六步生成链路。director_v2 以根目录 PRD v5.0、Tech Spec v5.0 和 Plan v6.0 为准；本文件的每章两项状态变化、声纹对话数量与机械阈值不得直接作为 v2 发布硬门，须按场景意图重新校准。

## 产品目标

系统交付的不是“字数达标的章节”，而是连续三章均有不可逆局势变化、人物可辨认、状态可追溯，并能让目标读者愿意继续付费阅读的小说。

## 发布门槛（P0）

任何一项硬门失败，章节不得自动发布，必须携带证据重写并重新评测：

| 能力 | 可执行需求 | 自动验收 |
|---|---|---|
| 相邻章去重 | 不复演上一章的场面、动作链、威胁台词 | 精确长句复用率 ≤12%，5 字符 n-gram Jaccard ≤0.30 |
| 净推进 | 每章结束必须改变至少两个持久状态 | `state_before/state_after` 至少 2 项不同；字数不算推进 |
| 状态一致 | 下一章开局继承上一章结局 | 同名状态零冲突；冲突必须有正文解释和显式事件 |
| 角色声纹 | 主要人物用词与句法不可互换 | 每角色至少 20 个有效对话字符；角色对二元语汇余弦相似度 ≤0.72 |
| 模板抑制 | 高频网文套句受控 | 默认模板短语密度 ≤3 次/万字；词表版本化、编辑可配置 |

自动指标仅用于发现确定性缺陷，不能宣称证明“文学性”。每次模型、提示词或生成架构变更，还必须通过 `fixtures/novel_quality/v1/human_editor_rubric.json` 的三人双盲人工验收：六项中位数均不低于 4/5，且沉浸、因果、人物可信度不得出现 1 分。

## P1 工作流需求

1. 规划端为每章写入起始状态、目标状态、必须发生的代价，以及本章禁用的最近桥段。
2. 生成端输出可审计的角色归属对话与状态差异，不允许质量器自行猜测说话者。
3. 审核端展示每项失败证据；只重写失败维度，重写后必须完整复审。
4. UI 同时展示“机器硬门”和“人工编辑结论”，不得把长度、流程完成率或单一综合分包装成质量。
5. 发布端以连续三章为最小验收窗口；单章通过不代表故事通过。

## P2 回归与运营指标

- 固定一套好/坏样本和至少 20 组真实连续三章盲测集，按题材分层。
- 版本发布比较旧版与新版的盲选胜率；新版需 ≥60%，95% 置信区间下界需高于 50% 后才全量。
- 线上跟踪三章留存、继续生成率、人工重写率和重复告警率；不得用生成字数替代质量指标。
- 阈值只能通过标注集校准并记录版本，不能为了让测试通过而临时放宽。

## 职责与完成定义

- 产品：维护门槛、目标读者和灰度发布决策。
- 小说编辑：维护 rubric、模板词表、盲评集及失败证据示例。
- 后端/算法：产出状态差异、角色归属及评测报告，失败阻断发布。
- 前端/UI/UX：让失败原因、章节对比、修改前后差异可理解且可操作。
- QA：在每次模型、提示词、上下文或采样参数变化时运行确定性回归与盲评。

完成定义：自动测试全绿；连续三章无 P0 失败；三名编辑盲评通过；新版本盲选胜率达到灰度标准；所有结论保留样本、版本和证据。
