# 小说 → 短剧工具转向可行性分析

> 版本：v1.0 · 日期：2026-09-22  
> 性质：内部决策分析（写实口径，不作对外宣传）  
> 范围：评估 `Novel-Engine-PRD/Tech-Spec/Plan v6.0/v8.0` 所定义的产品转向是否可做、值不值得做、怎么做才不翻车  
> 证据基准：当前仓库文档与代码、公开市场资料（见 §8）；未发起付费生成、未接触真实客户

## 0. 结论先行

### 0.1 总判定

| 维度 | 判定 | 一句话 |
|---|---|---|
| 技术改造可行性 | **FEASIBLE（有条件）** | 内核资产真实可复用；短剧交付层基本是新建，但不推倒重来 |
| 市场是否存在 | **FEASIBLE** | 微短剧 2025 年约 678 亿元、6.96 亿用户，产量以十万部计——需求真实 |
| 我们站的那一段值不值钱 | **REVISION_REQUIRED** | 钱主要在平台分账与制作；剧本/工具是薄段且已拥挤 |
| 质量能否达标 | **UNKNOWN / 高风险** | 小说方向的 LLM 质量瓶颈尚未突破，换媒介不自动解决 |
| 综合 | **有条件推进（Conditional GO）** | 允许投 SD-M0/M1 技术切片；**禁止**在客户与竞品证据冻结前扩大投入或对外承诺 |

**直接回答「这个改动可行吗」：文档转向本身正确且已做完；工程上可执行；商业上只有把差异化做对才成立。现在最大的风险不是改不动代码，而是把「AI 写剧本」当卖点——那条赛道已经很挤，而且会被通用大模型免费打穿。**

### 0.2 要花多少、多久、错了会怎样

| 问题 | 估算（假设 2 名全栈 + 1 名产品/主创兼职） | 说明 |
|---|---|---|
| 要花多少（到客户封测） | **人力约 4–7 人月**（SD-M0→M5）；模型调用费按现有 price_book 量级，12 集试验项目可控在数百～数千元级 | 不含销售/获客；不含 AI 视频链路 |
| 多久 | **粗区间 4–7 个月到可封测**；其中 SD-M0+M1（单集纵切）**6–10 周** | 计划本身也写明「不在缺少基线盘点时给出伪精确日历」——上表是规划用区间，不是承诺 |
| 错了会怎样 | 技术侧沉没有限（复用内核仍在）；**真正贵的是机会成本**——若 3 个月后发现创作者不为「一致性/改稿联动」付费，这批投入等于给竞品做了概念验证 | 回退路径：关闭 `drama_v1` 创建开关即可停新流量；旧小说链路不删（Tech-Spec 已定） |

### 0.3 三条硬建议（按优先级）

1. **差异化必须锚在「全剧一致性 + 联动改稿 + 制作约束 + 版本锁定」**，不能锚在「AI 帮你写剧本」。后者竞品密、且 ChatGPT/Claude 可替代。
2. **SD-M0 的客户访谈与竞品实测是 Go/No-Go 闸门**，不是并行可选项。技术切片可以先动，但 SD-M2 扩面投入前必须拿到「有人愿意为上述差异点付费」的初步证据。
3. **质量风险单独立项跟踪**。小说实验已经证明「故事讲清楚 ≠ 用户愿意看」；短剧把标准换成了「可表演、可拍、能过稿」，但底层仍是同一类 LLM 质量问题。SD-M1 出口必须带真人审阅证据，不能只过 schema。

## 1. 分析范围与口径

- **分析对象**：从「付费网文小说生成」转向「短剧创作者分集剧本工作区」这一产品方向变更，以及支撑它的工程改造。
- **文档现状**：转向已在 2026-09-22 完成文档侧落地——PRD v6.0、Tech-Spec v6.0、Plan v8.0 已替换小说契约；转向前快照在 `docs/archive/novel-before-short-drama-2026-09-22/`。
- **写实口径**：本文是内部决策材料。不按对外宣传口径放大能力；市场数字标注来源与口径差异。
- **明确不做**：不评 AI 视频/成片链路（PRD 首版已排除）；不为「替代便宜编剧人力」算账（见 §3.3）。

## 2. 市场可行性

### 2.1 市场规模（有量，但口径分裂）

| 指标 | 数字 | 来源与口径 |
|---|---|---|
| 2024 微短剧市场 | 504.4 亿元 | 《中国微短剧行业发展白皮书（2025）》（中国网络视听协会） |
| 2025 微短剧市场 | **677.9 亿元**，同比 +34.4% | 艾媒咨询《2025-2029 年中国微短剧市场研究报告》 |
| 2025「千亿」说法 | 突破千亿元 | 白皮书/媒体口径，含漫剧、衍生与更宽统计；与艾媒 677.9 亿**不是同一口径** |
| 用户规模 | 6.96 亿（2025）→ 报道称超 8 亿 | 白皮书 / 2026-09 广电总局回应报道 |
| 产量 | 月产 3000 部以上；2025 年独立制作量预计 4 万部；2026 年 1–8 月上线 43 万部（AI 剧占超九成） | 艾媒 / 白皮书 / 腾讯新闻 2026-09-17 |

**解读**：市场不是问题，**产能竞赛是问题**。43 万部上线、九成 AI 剧意味着——「能生成剧本」本身几乎没有稀缺性；稀缺的是「能被制作方收下、能拍、能过稿」的交付物。

### 2.2 钱被谁赚走（价值链）

```text
平台分账/投流  ──►  制作/拍摄  ──►  剧本/编剧  ──►  工具订阅
   （大头）           （中头）          （薄段）        （更薄）
 红果/抖音/快手     剧组、承制方      3–8 万/部买断     月费/点数
```

- **平台**：流量与分账规则主导收益，剧本买断价对平台/制作方是成本项，不是收入项。
- **制作**：设备/演员/投流才是大头支出；剧本费占比有限。
- **剧本**：供给过剩后，「普通编剧单本剧本报价腰斩至 3–8 万元」（公开行业稿酬盘点）；亦有 7500 元保底 vs 12000 元 AI 剧本的分化报道——说明**能被 AI 流水线用的剧本**开始有溢价，纯文学性剧本在贬值。
- **工具**：订阅/点数。客单取决于能否嵌入「过稿/开工」关键路径，而不是字数产量。

**按「钱在哪一段」判断**：我们做的（剧本工具）站在**最薄、且正在被 AI 大规模填平**的一段。可做，但**溢价必须可解释**——见 §3.2。

### 2.3 竞品密度（已拥挤，不是蓝海）

公开可见的短剧向工具至少包括（2026 年中评测/盘点口径，非穷尽）：

| 类型 | 代表 | 含义 |
|---|---|---|
| 短剧垂直剧本工具 | 创一 AI、StoryPlay 等 | 「AI 写短剧剧本」心智已被占位 |
| 批量量产型 | 巨日禄 AI、Seko AI 等 | 打「低成本高效率」，和我们卷产能必输 |
| 团队协作/资产型 | AniShort、LibTV 等 | 打协同与资产复用 |
| 个人全流程型 | 小云雀 AI、马上短剧等 | 打单人出片 |
| 通用大模型 | ChatGPT / Claude / Gemini | 免费或订阅即可写分集；在脑暴和局部改稿上已够用 |

**含义**：若产品叙事是「AI 帮你写短剧剧本」，发布当天就进入红海，并被通用大模型侧击。必须换叙事（§3.2）。

## 3. 产品与商业可行性

### 3.1 PRD 已选对的问题（值得肯定的部分）

PRD v6.0 有三处判断是对的，应保持：

1. **交付物是「完整可制作的分集剧本」**，不是「字数达标的章节」或内部提纲——对准的是制作方收稿标准。
2. **创作者控制权 + 人工改稿 + 版本/拍摄锁定**——这是通用聊天工具做不好的工程问题。
3. **首版不碰 AI 视频、不做公共阅读/广告分成**——避免摊大饼。

### 3.2 可解释的溢价在哪里（必须成立的差异化）

| 能力 | 为什么对手难抄 | 付费理由（给创作者） |
|---|---|---|
| 全剧结局先行 + 跨集事实/悬念兑现 | 通用 LLM 无持久项目态；单次对话接不上 12 集依赖 | 少写崩、少返工 |
| 改一句 → 联动影响面 + 修订分支 + 原子切换 | 工程重，不是 prompt 能解决 | 改稿往返时间下降 |
| 制作硬限制（演员/场地/道具/时长） | 需要领域模型与校验器 | 稿子能拍、能过审 |
| 定稿/已拍摄锁定 | 版本治理 | 对接制作流程不背锅 |

**溢价公式（写实）**：  
> 卖的不是「写得更快」，而是「改得起、锁得住、拍得了」。  
> 对照物不是「雇一个编剧」，而是「通用 LLM + 人肉整理一致性」的时间与翻车成本。

### 3.3 不做什么账（红线）

- **不做「替代便宜人力」账**：短剧编剧稿费在过剩后并不贵（单本 3–8 万，且大量新人接不到活）。用「省编剧工资」算 ROI 不成立。
- **价值类型对照**（若要用不与人力成本竞争的框架）：主要是 **时间**（连续产能与改稿往返），其次是 **空间**（一人盯多部的一致性）；**不是**省钱。
- **不承诺爆款、过稿率、收益**——PRD 已写明，对外必须守住。

### 3.4 目标客户与付费假设（未验证，标为假设）

| 假设 | 当前状态 | 验证时点 |
|---|---|---|
| 独立编剧/小团队主创愿为「一致性+改稿工程」付订阅 | **未验证** | SD-M0 访谈 + M5 封测 |
| 默认低成本真人短剧是对的切入 | **未验证**（AI 漫剧产量已占九成，方向可能错位） | SD-M0 必须二选一并记录不适用客户 |
| 12 集 / 90–120 秒 / 4 角色 / 3 场地是合理工程样本 | 样本假设，可改 | SD-M0 冻结 |
| 订阅或项目额度优于按集买断 | **未验证** | M5 后 |

**批判点**：PRD 把「真人 or 漫剧」放在 SD-M0 冻结是对的。但公开数据（2026 年 1–8 月 AI 剧占上线量超九成）暗示——**若客户实际在做 AI 漫剧流水线，首版「低成本真人」设定可能直接错过需求**。这应作为 SD-M0 访谈的**第一优先问题**，不是流程后置项。

## 4. 技术可行性

### 4.1 代码资产盘点（写实）

| 资产 | 规模/证据 | 对短剧的复用价值 |
|---|---|---|
| `regent.novel` 包 | 92 个 py 模块，约 3.0 万行 | **高**：导演循环、记忆、预算账本、恢复、作品生命周期 |
| `script_protocol` / `directing_*` | 多候选 script/script_scene 协议 | **中**：候选机制可留；契约含 `WRITE_CHAPTER`/`ACCEPT_CHAPTER` 与 `WEB_NOVEL_POWER_CONTRACT`（金手指）须隔离 |
| `prose_*` 正文门禁 | prose 字数/网文规则 | **低（负资产）**：短剧须禁入；Tech-Spec DG-01 已立守卫 |
| 账本/租约/恢复/price_book | 内核级 | **高**：SD-12 直接复用 |
| `apps/novel-web` | 仅 `App.tsx`/`ui.tsx`/`api.ts` 等少量文件 | **低**：剧本工作区 UI 基本是新建 |
| 测试 | 顶层 222 个测试文件 | **中**：旧小说回归有价值；短剧验收须另建 |
| Regent Core | 超出 novel 的通用内核 | **中**：按端口复用，不扩产品使命（Regent-PRD 已收敛） |

### 4.2 新建 vs 复用 vs 淘汰

```text
复用（内核）                新建（产品层）                 淘汰/隔离（小说层）
─────────────              ────────────────               ─────────────────
导演循环、调用底座    →     drama_v1 执行协议/AST     ✗    网文金手指契约
记忆/事实/悬念账本    →     EpisodeEdition/分场正文    ✗    prose 字数门禁
预算/账本/租约/恢复   →     制作约束校验器             ✗    公共阅读/广告分成
works 生命周期/API    →     版本/锁/修订分支           ✗    150 章认证路线
                          影响面分析与联动改稿
                          TXT/DOCX 导出快照
                          剧本工作区编辑器
```

### 4.3 主要技术风险

| 风险 | 等级 | 依据 | 缓解（已在计划中的） |
|---|---|---|---|
| 内部 script 被误当短剧正文 | 高 | 现协议 `WRITE_CHAPTER`/`ASSEMBLE_CHAPTER` 仍是小说正文语义 | M1 drama_v1 + DG-01 隔离测试 |
| 迁移把旧作品改型 | 中 | `work_type` 若默认不当 | 旧记录默认 NOVEL；在途 run 固定协议 |
| 人工改稿被 AI 覆盖 | 高 | 小说链路无「场/块级编辑权」概念 | M2/M3 版本递增 + 冲突保留 |
| 改前集导致后集失效 | 高 | 依赖图是新问题 | M3 ChangeRequest + 修订分支 |
| 前端工作区能力缺口大 | 中高 | novel-web 过薄，非简单皮肤替换 | M2 最小编辑器组件；先 CLI/预览不算完成 |
| 质量门靠模型自评 | 中 | 历史实验已显示自评失真 | 强制人评 + 预登记门槛 |

### 4.4 技术结论

**改造不是重写，但也不是换皮。**  
可复用的是「怎么安全地花钱、记账、恢复、推进长任务」；必须新建的是「短剧是什么」（AST、约束、版本、锁、导出、编辑器）。  
Tech-Spec v6.0 的增量迁移方案（`work_type`、`drama_v1`、feature flag、fail closed）是合理工程路径，**按计划做是可行的**。

## 5. 工程量与成本

### 5.1 里程碑工作量区间（规划用，非承诺）

| 阶段 | 产出 | 人力区间（人周） | 累计到出口 |
|---|---|---|---|
| SD-M0 规格/盘点 | 样本、差异清单、schema 草案、评测方案 | 2–4 | 2–4 |
| SD-M1 单集纵切 | 一集真稿 + 预算恢复 | 4–8 | 6–12 |
| SD-M2 全剧+三集+编辑 | 主路径工作区 | 6–10 | 12–22 |
| SD-M3 改稿联动+锁 | 依赖修订/拍摄锁 | 6–10 | 18–32 |
| SD-M4 12 集+导出 | 完整样本与盲评 | 4–8 | 22–40 |
| SD-M5 封测+灰度 | 真实客户证据 | 4–6 | 26–46 |

→ **26–46 人周 ≈ 4–7 人月**（2 人并行约 2.5–5 个月到封测；1 人则翻倍）。  
与 Plan §3「SD-M0 结束后按实际复杂度估人日」一致；M0 做完应更新本表。

### 5.2 模型与运行成本（数量级）

- 仓库已有版本化 `price_book`（DeepSeek/GLM/Qwen 等，按每百万 token）。
- 12 集工程样本 + 多候选 + 改稿重算：**数百元～数千元人民币级**可控，不是阻塞项。
- 真正贵的是**失败重试与废稿**——M1 的「无效修复止损」直接打成本。

### 5.3 机会成本（更重的账）

若团队 3–5 个月全力投入后，验证失败：
- **留下的**：可复用内核、短剧 schema、锁/版本工程、评测方法。
- **丢掉的**：同期未做的其他方向（龙虾机、eSIM、AgentOS 等业务线时间）。
- **判定**：以「技术切片 + 客户证据」并行的方式投入，机会成本可接受；若一上来做全量工作区再找客户，不可接受。

## 6. 质量风险（历史教训直接迁移）

小说方向的质量实验结论仍然致命，且**不因换媒介自动消失**：

- 历史记录：「故事都讲清楚了，但没有阅读动力」「根因在开场钩子与类型预期，不在调度」。
- 短剧的门从「想继续读」换成「能拍、能演、能过稿」——**门槛对象变了，门槛高度没降**。
- LLM 生成「结构正确但戏剧平庸」的稿子，schema 校验全绿，人评打回——这是最可能的失败形态。

**因此：**

1. SD-M1 出口必须是「真人愿意签收的一集」，不是「schema 通过的一集」。
2. 质量门槛在 SD-M0 用 5–10 个样本 pilot **预登记**，禁止事后调门。
3. 北极星用 PRD 的「每周接受并用于制作的剧本分钟数 + 人工修改时间」，**禁止**用字数/调用量粉饰。

## 7. 综合决策建议

### 7.1 判定汇总

| 问题 | 回答 |
|---|---|
| 文档转向对不对？ | **对**。旧小说契约（禁改稿、公共阅读、150 章认证）已失去客户基础；短剧是相邻能力迁移。 |
| 工程上做得动吗？ | **做得动**。内核复用真实；产品层新建量清晰；增量迁移方案合理。 |
| 商业上值得吗？ | **有条件值得**。市场有量，但必须站在「工程化剧本交付」而不是「AI 写作」那一段。 |
| 最大翻车点？ | ① 质量不达可拍标准；② 差异化被通用大模型抹平；③ 首版「真人短剧」与真实客户（可能偏 AI 漫剧）错位。 |

### 7.2 Go / No-Go 闸门

```text
现在 ──► SD-M0（样本+盘点+访谈）──┬──► 有付费/采用证据 ──► SD-M1/M2 加速
                                  │
                                  └──► 无证据或差异化不成立 ──► 停在内核资产，不扩工作区
```

- **允许现在就做**：M0-02/03/04/06（样本、代码差异清单、schema 草案、迁移备份）——无市场依赖，纯工程。
- **必须做完再加码**：M0-01/05（客户访谈、评测预登记）之上的 SD-M2+ 产品面投入。
- **明确禁止**：未冻结质量门前启动 AI 视频/成片/多题材并行；用小说历史验收勾选宣称短剧完成。

### 7.3 若只做一件事
