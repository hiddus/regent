# 导演生成质量与资源治理：下一版方案

日期：2026-09-11；状态：**部分已实施**（BQ-1/2、场景协议 @2、保守章窗口重演、记忆逻辑槽 fact/known/promise/summary、legacy 执行体退役）。DB 仍存细 kind；投影边界保留。

## 本轮证据

只读数据库端统计最近五个运行：调用次数依次 78/109/120/60/94；对应费用整数单位 494/513/663/260/503。只有 109 次运行 CANONIZED，其余为 TERMINAL_FAILED/WATCH_PROSE。不是随机样本，不能当作长期成功率。远程只取统计字段，没有导出正文或完整上下文。

本地代码 MAX_CALLS=120、MAX_COST_MINOR=20000；**BudgetExhausted 已走作品 PAUSED_***（不再直接 TERMINAL_FAILED）；其它 ProductionStopped 仍可终态失败。

F4 本地记录已有同次补丁后成章证据，应保留；单次通过并未解决当前调用密度与质量问题。本轮未重新跑单测、未部署、未调用真实生成模型。

## 第一步：可恢复预算暂停与分阶段观测（优先实施）

- 把停止原因区分为调用额度、金额额度、局部修复次数、模型/网络故障、契约失败和真实内容矛盾。
- 全局调用/金额额度不足进入明确的预算暂停，保留已接受场景、当前稿、错误报告和待执行动作。前端显示已完成范围、停止原因、下一步及预计额外成本；不得显示仍在生成。
- 恢复不清零作品累计账、不重复生成已接受内容。追加额度必须显式授权；无额度也能查看/导出草稿。局部修复耗尽不得通过暂停再恢复无限重置。
- 按 phase/take/repair 统计调用、token、费用、时延、硬问题数及其变化。诊断报告先回答钱和调用耗在何处，再改路由。

验收：额度不足发生在 provider 前；重启不重计费；用户授权后从原检查点继续；终止/暂停 UI 诚实，自动 Worker 不反复领取耗尽任务。

## 第二步：增加修复进展判据，停止无效循环

- 对硬问题建立稳定标识，记录每次修复是解决、新增还是重复；字数增长和模型自评分不能当作修复有效。
- 若同一失败重复且输入没有实质改动，停止同类自动重试并回到导演重新规划。导演仍决定改场景、修改叙事方案或等待用户，不自动将 REWRITE 换 RETAKE。
- 每次修订仅发相关问题、必要事件和对应段落；完整合并稿继续核验。保留通过的场景与产物版本，避免从头重做。
- 在发起下一步前预留生成、核验和最终提交的预算，避免正文生成花光全部调用后无法验收。比例从测量确定，不先拍固定百分比。

验收：固定重复失败样本在有界次数内给出明确状态；确有进展的合法修订不被误杀；补丁/全稿 hash 与硬门不变。

## 第三步：减少不必要的逐节拍模型往返（独立版本试验）

导演保留场景意图、冲突组织、重要人物选择、重演、取舍和终局权。将低风险、依赖已明确的动作组成小段行动计划后统一结算，在会改变方向、暴露秘密或出现矛盾的边界返回导演。不能把有前置依赖的角色动作盲目并发。

文学细节与客观世界状态分层：关键事实、知识变化、承诺、物品/位置变化继续硬核验；非持久姿态和表达细节由导演审美判断，不无限膨胀成状态要求。哪些细节属于关键事实由规则与场景意图明确，不以降低错误数量为目的删除要求。

先评估一个有小范围目标的场景切片；与当前实现使用相同模型和预算，比较每个被接受场景的调用数/成本、事实漏检、重复修复和阅读评价。未证明改善前不默认替换生产策略。

## 第四步：把质量目标前移并形成对照

场景开始前明确人物想要什么、选择及代价、读者应感受到的变化、需要兑现/新埋的承诺与场景结束条件。不要将“核验通过”视为“好看”。

冻结输入与样本，记录所有成功/失败，不以替换失败运行凑足成功数。自动比较完成率、调用数分布、每个有效章节成本、真实事实错误；人工盲评阅读意愿、人物可信度、节奏与情绪兑现。跨章和长篇实验在首章调用效率稳定后逐级进行。

## 实施决策

下一批先实施第一、二步，形成一次完整的“预算暂停→授权续作→接受章节”与“无效修复及时停止”验收。第三步作为保留导演创作权的另一策略版本逐步试验。暂不提高 MAX_CALLS、换更贵模型或增加无条件自修次数；这些选项只能由同预算对照证据支持。
