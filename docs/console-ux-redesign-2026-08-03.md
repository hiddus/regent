## 0. 一句话结论

> 今天的控制台是「功能都挂上了的折叠墙」；目标应变成：  
> **对话是主叙述，工作区是可切换的证据面，闸门是同一族卡片，Stop 永远一等。**

当前痛点不是缺能力，而是 **同一屏上有太多并列真相**（StageBar + 进度卡 + Agent 名册 + 清单 + 活动流 + 源码 + 审阅 JSON），用户不知道该看哪一块。

## 1. 现状诊断（产品 / 交互 / UI）

### 1.1 产品：语义打架

| 冲突 | 文档 A | 文档 B | 代码现状 |
|------|--------|--------|----------|
| 右侧默认主视图 | PRD §4.3.2：**Agent 名册** | Hybrid §3.1 / Work Plan：**工作清单** | 名册默认，清单折叠，用户「计划看不到」 |
| 确认 vs 续跑 | PRD：确认是纠偏非门闩 | OpenWork：大改须 plan_approve | 多卡并存，文案/按钮语义不统一 |
| 看得见 | 可观测性方案要求事件驱动 | 审阅仍 JSON dump | 活动流、工具事件、进度节点三套并存 |

**拍板建议（本方案）**：运行中右侧默认 **工作清单**；Agent 名册降为「运行」Tab 内次要区。PRD §4.3.2 同步修订为「清单优先，名册可见」。

### 1.2 交互：折叠墙 + 控制分散

```text
今天右侧（自上而下堆叠）
  结果 / Ask|Act / Trust / 侧问
  参与 Agent（主）
  工作清单
  时间线
  活动流
  源码
  产物预览
  审阅 JSON
```

问题：
1. **没有「当前该看什么」**：一切默认或靠手动展开，无情境切换。  
2. **闸门分裂**：`ConfirmationCard` / `TaskCard` / `RecoveryCard` / StageBar 按钮各说各话。  
3. **Stop 不够一等**：夹在 StageBar 快捷钮里，与「批准/拒绝」同权视觉。  
4. **对话与证据脱节**：点进度卡看不到对应文件/预览；点清单项看不到对话里的那一步。

### 1.3 UI：无设计系统、无工作区原语

- 自研暗色 + ChatGPT 绿感 accent + system 字体  
- 无 Tab / Segmented / Drawer / Toast 统一原语  
- 卡片圆角、边框、间距各组件自写  
- 移动端仅侧栏抽屉，右侧面板体验弱

| # | 用户想做什么 | 目标体感 |
|---|--------------|----------|
| U1 | 开一个目标 | 空态一句目标 + 示例；发出后立刻见「拟议方案」卡，不是空白转圈 |

## 3. 信息架构（一构图）

对齐 OpenHands「对话 + 可切换工作区」，保留 Regent 的 Goal/清单/治理语义。

```text
┌─ App 轨（窄）─┬─ 对话轨（主）─────────────────┬─ 工作区轨（证据）──────┐
│ Regent        │ 顶栏：目标名 · 阶段微标 · 连接  │ [清单|运行|改动|预览|审阅] │
│ + 新建        │                               │                         │
│ 项目列表      │  消息流 / 流式 / 闸门卡 / 结果卡 │  当前 Tab 内容            │
│               │                               │                         │
│               │  底栏 Composer + [停止]         │  Ask|Act（钉在清单 Tab）   │
└───────────────┴───────────────────────────────┴─────────────────────────┘
```

### 3.1 三轨职责

| 轨 | 职责 | 不做 |
|----|------|------|
| **App 轨** | 选 App / 新建 / 终态归档开关 | 设置页堆砌；多 Goal 运营 Hive（H3） |
| **对话轨** | 唯一自然语言入口；叙述、闸门、结果 | 塞文件树、长 JSON、甘特 |
| **工作区轨** | 证据与运行态（清单/Agent/文件/预览/审阅） | 第二套聊天；第二套审批 |

### 3.2 工作区 Tab（替换折叠墙）

| Tab | 默认何时激活 | 内容 |
|-----|--------------|------|
| **清单** | 有 plan 且未 COMPLETE | Work Plan；Ask\|Act；堵点时嵌简易依赖条 |
| **运行** | 无 plan 或用户点开 | Agent 名册 + 活动流（事件驱动，非中文反解） |
| **改动** | 有文件树/diff 信号 | 源码树 + 文件内容（日后 diff） |
| **预览** | 预览 URL 就绪时自动切一次 | iframe + 下载 |
| **审阅** | COMPLETE / 用户点开 | 计划摘要、验证结论、预算——**结构化卡片，禁裸 JSON 当默认** |

时间线（H2）：默认藏在清单 Tab 内「依赖视图」开关；无依赖不展示入口。

### 3.3 顶栏瘦身

- **去掉** StageBar 上与闸门卡重复的「批准/拒绝」主路径（闸门只在对话卡上决断）。  
- **保留** 阶段微标（理解…结果）+ 连接态；进度条改为 **清单完成比**（`done/total`），假 10 段进度条降级或删除。  
- **停止 / 暂停 / 恢复**：收到顶栏右侧「运行控制」组；Stop 视觉权重最高。

## 4. 交互范式

### 4.1 统一闸门卡片族 `InterventionCard`

同一视觉壳，三种 `ask_type`（Hybrid §3.3）：

| ask_type | 标题语气 | 主操作 | 次操作 |
|----------|----------|--------|--------|
| `plan_approve` | 「请确认本轮计划」 | 批准并继续 | 修改方向 / 停止 |
| `permission` | 「需要授权：{tool}」 | 允许一次 · 本会话允许 | 拒绝 |
| `ask_user` | 「需要你选一个方向」 | 选项 A/B/C（带代价） | 补充说明后继续 |
| `recovery`（软暂停） | 「卡住了，建议这样继续」 | 推荐动作 | 停止 · 自行补充 |

规则：
- 「总是允许」**仅** `permission`，且文案为「本会话允许」；交付缺口 / 软暂停 **禁止**该按钮（PRD §4.3.6）。  
- Recovery ≠ Permission；不得共用「允许」文案。  
- 历史闸门收敛为紧凑一行，可点开复看。

### 4.2 对话流分层（吸收 Claude / Cursor）

```text
用户消息
助手叙述（可流式）
  └─ 工具轨迹（默认折叠一行：「读了 3 个文件 · 写了 app.py」；展开见摘要）
进度节点（进行中 = detail；结束后 = overview → 可 compressed）
闸门卡（置顶于流末，未决时 sticky）
结果卡 COMPLETE（摘要 + 打开预览/审阅 + open_items）
```

滚动：贴底跟随、上滚锁定（保持现状）。心跳/重复 progress **原地替换**。

### 4.3 清单 ↔ 对话联动

- 清单项点击 → 对话滚到关联进度/工具段（有 `item_key` 时）。  
- 对话中「卡在第 k 步」的 ASK → 自动打开清单 Tab 并高亮该项。  
- 同时最多一条 `in_progress` 视觉强调（粗条/左侧色条）。

### 4.4 模式与信任

- Ask\|Act 放在 **清单 Tab 顶**，不埋进折叠。  
- 切到 Act：轻确认「清单内连跑；删除/外发仍询问」。  
- Trust 姿态：收进运行 Tab 或顶栏 overflow，不占结果面主位。  
- 侧问：Composer 旁 `⌘/` 或「快问」次按钮，不占右侧首屏。

### 4.5 空态与完成态

| 态 | 主区 | 工作区 |
|----|------|--------|
| 无 App | 品牌 + 一句目标示例 + Composer | 隐藏或示意「产物会出现在这里」 |
| 规划中 | 方案卡 | 清单「尚未规划」骨架 |
| 执行中 | 叙述 + 工具 | 清单主 |
| 等待人 | sticky 闸门卡 | 清单高亮 blocked |
| COMPLETE | 结果卡置顶 | 自动切预览或审阅 |
| FAILED | Recovery / 选项化失败卡 | 审阅 Tab 打开验证结论 |

## 5. UI 视觉语言

### 5.1 原则

- **一张构图**：首屏 = 品牌弱化在 App 轨 + 对话英雄区 + 工作区证据；禁止仪表盘式多卡墙。  
- **一节一事**：工作区每次只展示一个 Tab 的完整内容。  
- **闸门高对比**：未决卡用边框/左侧色条，与普通消息区分；Stop 用危险色，不与 accent 混用。  
- **克制动效**：闸门出现、Tab 切换、清单勾选 2–3 处有意动画；禁止进度条闪烁噪音。

### 5.2 Token（在现有暗色上收敛，不换皮重做）

| Token | 建议 | 说明 |
|-------|------|------|
| `--bg` / `--panel` | 保持深底分层 | App 轨略深于对话轨 |
| `--accent` | 保留或微调为「继续/批准」 | **不再**用于 Stop |
| `--danger` | 新增明确红 | 仅 Stop / 拒绝后果 |
| `--warn` | 新增 | 等待人、软暂停 |
| `--font-ui` | 可选引入一款 UI 字体（如 IBM Plex Sans / Source Sans） | 避免纯 system；不作装饰衬线英雄 |
| 圆角 | 统一 `6/8/12` 三档 | 卡片 8，按钮 6 |
| 间距 | 4 的倍数 | 对话气泡与工作区对齐 |

**避免**：紫系渐变、奶油衬线海报风、过多 pill、多层 glow。

### 5.3 组件原语（先小后全）

本阶段只抽控制台必需：

1. `AppShell`（三轨 grid + 响应式）  
2. `WorkspaceTabs`  
3. `InterventionCard`  
4. `ResultCard`  
5. `PlanList`（清单）  
6. `RunControls`（Stop/Pause/Resume）  
7. `ToolTrace`（可折叠工具行）  
8. `EmptyState`

暂不引入 Ant Design / MUI；若后续要无障碍焦点管理，可只加 Radix Tabs/Dialog 头，不换整库。

### 5.4 响应式

| 宽度 | 布局 |
|------|------|
| ≥1200 | 三轨并存 |
| 768–1199 | App 轨抽屉；对话 + 工作区；工作区可半宽 |
| \<768 | 默认对话全宽；工作区底部 sheet / 全屏 Tab；Stop 仍固定可见 |

## 7. 分期落地（体验面，不重开 H0）

内核 H0–H2 已基本到位；本重梳是 **皮肤 + IA + 卡片统一**，按风险切片：

### Wave UX-0 — 止血构图（约 3–5 天）

- 右侧折叠墙 → `WorkspaceTabs`（清单默认）  
- 顶栏：RunControls 一等 Stop；去掉与闸门重复的批准主路径  
- 清单完成比替换假 10 段条（或并存一期后删）  
- Ask\|Act 钉到清单 Tab 顶  

**验收**：新用户能在 10 秒内找到「现在在干什么」和「怎么停」。

### Wave UX-1 — 闸门与结果（约 3–5 天）

- 合并三卡 → `InterventionCard`  
- COMPLETE `ResultCard`（摘要/产物/open_items）  
- 失败交人带 2–3 选项（PRD §4.3.5）  
- 审阅 Tab 结构化，JSON 进「高级」  

**验收**：所有等人场景只有一种卡脸；完成必见结果卡。

### Wave UX-2 — 叙述与联动（约 1 周）

- `ToolTrace` 折叠行；进度节点与清单 `item_key` 联动  
- 堵点自动开清单 + 高亮  
- 侧问挪出右侧首屏  
- 基础 token / 字体 / 空态统一  

**验收**：长会话可扫；点清单能回到对话对应步。

### Wave UX-3 — 打磨（按需）

- 改动 Tab diff  
- 时间线依赖视图开关  
- 移动端 sheet  
- 可选 Radix 无障碍
