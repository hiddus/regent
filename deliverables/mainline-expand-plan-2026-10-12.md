## 目标

新作品在编剧动笔前有一份审过的主线。章内仍走现有的选题、剧本、分场、正文。分场卡上的格式错误由程序改正后继续写。和主线冲突的正文仍然停章，不入正史。

验收：一部新作品自动写完 3 章，三章均为 CANONIZED 且 word_count > 0。主线节点顺序与三章正文的因果一致，没有把同一件已发生的事再演一遍。

## 已在工作区、尚未提交

- 编剧选题前调用 `_ensure_story_mainline`：没有主线就生成 10–16 个节点并审一次；审不通过按意见改一版，然后进入现有流程。
- 当前章走进主线覆盖范围的后三分之一（`chapter_no * 3 > node_count * 3 * 2`）时，顺着末尾节点再续 10–16 个节点，审过再写。已走过的节点不改。
- 编剧载荷带 `story_mainline.current / previous / following`。剧本必须推进当前节点。

这三步是本计划的工作包 1，合入前补测试：无主线会生成；已审过且未到三分之二不再调用模型；续写只追加、不改已走节点。

## 仍然会停章的格式错误

服务器上第 1 章实际停过的，以及同类格式问题，程序能改的必须改完再校验，不能把原错误原样退回模型直到 `ProductionStopped`：

| 错误 | 程序处理 |
|---|---|
| 同一 event_id 多次 occurrence | 保留最早一场，其后改为 reference（已有） |
| 发生类事件的后场标成 consequence | 改为 reference（已有） |
| 回忆类事件标成 occurrence | 改回 reference（已有） |
| 责任场没有 occurrence，但节拍是清单外的新行动 | 义务留在该场（已有） |
| 自审把整段唯一情节标成删除 | 改记语义，不删情节（已有） |
| 自审点名的短句仍留在改后计划 | 程序删掉该短句再复验（已有） |
| 前检退回分场导致同一调用编号、不同入参 | `compile_epoch` 换号（已有） |
| `duplicate_event`：后场节拍整段包含前场长文本 | 删掉后场那条重复节拍；若该场因此没有节拍，保留一句不与前场重复的 purpose，不停章 |
| `duplicate_scene_id` / `duplicate_beat_id` | 后出现的 id 加后缀，保证章内唯一 |
| 分场超过 4 张 | 保留前 4 张，把被裁场的 occurrence 并入最后一张保留场；并入后仍走 occurrence 去重 |
| `constraint_present` 短句 | 继续由程序删除 |
| `constraint_missing`：要求出现一句计划里没有的新句子 | 降为语义 OPEN，不因此停章，也不替模型补写句子 |

以下情况仍然停章，不入正史：

- 事件编号不在剧本事件清单里，程序无法对照主线改标签。
- 同义换名重演（两条不同 event_id 描述互相包含）。不按字形合并名字。
- 正文与已审主线的当前节点冲突：当前节点的 promise 在选定剧本和分场里都没有落地，或写了后续节点才允许发生的事。
- 台账上的真实硬矛盾：已毁道具复现、同一访问轮次内再次离开、能力读取被标成普通阅读。沿用 10-11 计划，不 coerce 进正史。

## 工作包

### 1. 合入主线门

交付：`story_mainline.py`、`directing_script_loop._ensure_story_mainline` 与单测。

进入下一步：全通过路径上，主线已审且未到三分之二时，本阶段模型调用为 0。首次建立和到达三分之二各增加「生成 + 一次审核」，审核不通过才有第二次生成和复审。

### 2. 分场格式改由程序收口

交付：`scene_card` 或 `script_events` 中的纯函数，在 `validate_plan_event_refs` 与 `validate_scene_plan` 之前执行。`_ground_plan` 调用它们。改完再校验。校验结果里不再出现上表「程序处理」那一类错误。

`duplicate_event` 用现有规范化规则（去标点后长度 ≥ 24，且后场文本包含前场或相反）。只删后场重复条，不改前场。

进入下一步：用 a1da 的失败分场（`s2/b11` 与 `s3/b15` 同段开头）离线跑通，不再得到 `分场覆盖校验失败：duplicate_event`。

### 3. 主线落地检查

交付：选定剧本和分场之后、开写之前，程序检查当前节点的 promise 是否被任一节拍或剧本 `end_change` 覆盖（沿用 `_text_covers`，窗口不足时看节点标题里长度 ≥ 6 的专名是否出现）。未覆盖则带该节点原文打回编剧一次。第二次仍未覆盖则停章，原因写明节点标题与缺失的 promise。

这是故事矛盾，不是格式错误。只打回一次，避免在分场格式上循环。
